## Что это

Мия — self-hosted агент одной семьи, который живёт в Telegram. Проект вырос из
[Osinara](https://github.com/nyxandro/osinara) (nyxandro) и развивается отдельно: свой установщик,
собственные релизы и обновления, характер Мии, родной коннектор DeepSeek, гибридная память
и навыки с проверяемыми пробными прогонами.

Мия говорит по-русски от лица молодой девушки, на «ты», с живым юмором и собственным мнением. Она понимает голосовые,
помнит людей и договорённости между сессиями, сама напоминает о делах, ищет в интернете, разбирает фото и документы
и доводит задачи до результата через инструменты: файлы, документы, браузер, sandbox.

Ключевое отличие от обычного бота: **права не живут в промте**. Кто ты, из какой ты семьи, что тебе доступно
в этом чате — определяется проверенным Telegram-апдейтом и базой, а не текстом от модели. Личная память
никогда не попадает в групповой чат, внешняя группа никогда не получает доступ к личным данным и сервисам.

**Рассчитана на:** одну семью на своём сервере. Один владелец, приглашённые участники, закрытые семейные группы
и отдельно — внешние группы (рабочие, дружеские, клубные), где Мия работает в урезанном режиме с точечно выданными правами.

| Блок | Что умеет |
| --- | --- |
| Характер | Тёплая, внимательная, остроумная собеседница, а не служба поддержки. Без канцелярита и дежурных фраз, на хамство отвечает одной репликой с зубами, чужого не пересказывает. |

| Расписания | Напоминания и автономные сценарии по расписанию с инструментами; для внешних групп — отчёты с подтверждением владельца. |
| Голос | Groq Whisper до основного хода агента с повторной проверкой прав. |

## Функционал

### 💬 Мия как собеседник

- Инструкции задают разговорный стиль: сначала суть, потом детали, без дежурных вводных. Это настройки поведения модели, а не гарантия формулировок каждого ответа.
- Юмор часть голоса: замечает смешное одной точной репликой, дружески подкалывает того, кто сам в таком тоне, и убирает шутки там, где человеку плохо или речь о деньгах и подтверждениях.
- Своё мнение говорит, когда спрашивают. Ошибку признаёт прямо и сразу исправляет.
- Использует переданные в контекст время и часовой пояс. Для напоминаний часовой пояс и параметры уведомлений нужно настроить.
- Ответ может прийти несколькими сообщениями, как в живой переписке; пока идёт долгая работа, присылает короткую отбивку, что делает прямо сейчас; на «спасибо» ставит реакцию из набора, разрешённого в чате.
- Пожелания к стилю сохраняются на чат: короче, без смайлов, другой язык, свой формат. Личность и права такими настройками не меняются.

### 🧠 Долговременная память

- **Карточка человека.** Профильные записи имеют слот `attribute` (город, работа, машина, здоровье…); перед изменением занятого слота Мия читает все текущие записи и явно выбирает дополнение или замену. Устаревший набор ссылок отклоняется, независимые детали сохраняются. Мия может дать характеристику участника по накопленному.
- **События с датой.** Эпизоды хранят `occurred_at`; поиск понимает окно «что было в августе», окно поиска учитывает дату события. Срок удержания начинается с момента, когда Мия узнала факт, поэтому недавно узнанное старое событие не считается забытым.
- **Нити.** Незакрытые сюжеты (поиск квартиры, ремонт, лечение) поднимаются сами, когда тема возвращается.
- **Тихий review.** Минутный диспетчер формирует батч из 1–50 непроверенных сообщений: при накоплении десяти, после десяти минут тишины при хотя бы пяти или после шести часов тишины при любом ненулевом количестве. Группа может включить хвост в обычный адресованный ход от восьми сообщений. Для понимания добавляются до 20 предыдущих проверенных сообщений и уже сохранённая память. Личная история начинает проверяться с курсора 0; решение о сохранении принимает основной агент через `remember`.
- Каждая запись привязана к источнику: можно спросить «откуда ты это взяла». Конфликтующие версии сохраняются как наблюдения; агенту предписано учитывать обе и не скрывать конфликт упрощающей правкой.
- Гибридный поиск: морфологический и точный FTS плюс `multilingual-e5-small` в pgvector, объединение через RRF, затем локальный многоязычный MiniLM reranker. После ранжирования повторно проверяются права доступа. Эмбеддинги и переранжирование вычисляются локально; отобранные записи включаются в контекст основной модели и передаются её провайдеру.
- При недоступности E5 остаётся текстовый поиск, при сбое reranker сохраняется гибридная выдача. Расширенный поиск возвращает косвенные совпадения с пометкой слабой связи.
- Использование записи учитывается отдельно от подтверждения факта; повтор одного вызова не накручивает счётчики. Мягкое удаление сохраняет окно восстановления.
- Отдельные области `personal`, `family`, `group`. Экспорт личной памяти в JSON и Markdown.

### 🔍 Веб-поиск и vision

- `web_search` использует серверный поиск DeepSeek. Инструкции требуют проверять актуальные сведения поиском; `web_fetch` загружает конкретный известный адрес.
- Фото из сообщения, reply-цепочки или доступного файла анализирует настроенная ветка `agent.models.vision`. На текущем production её ID — `deepseek-flash`, как и у основной модели. Поддерживаются статические JPEG, PNG и WebP; доступ проверяется перед чтением.
- Во внешних группах поиск и vision выдаются владельцем точечно.

### 🎨 Генерация картинок

- При настроенных ключах Flux-цепочка использует FLUX.2 klein-4b на Cloudflare Workers AI, затем NeuralDeep. Доступность инструмента и состав цепочки зависят от подключённых провайдеров.
- Для Flux используются размеры 512×512, 768×512 и 512×768; формат файла определяется по байтам, результат сохраняется в рабочую область. Отправка защищена от повторного выполнения.
- При отказе фильтра содержимого инструмент возвращает подсказку переформулировать запрос.
- При провайдере `codex-subscription` доступна генерация через `gpt-image-2`. Это отдельный путь создания картинок, не модель для анализа фото.

### 🧩 Свои навыки

- Владелец говорит «сделай себе навык для …» или Мия сама предлагает после задачи в несколько шагов; сохранение всегда через кнопку владельца.
- Навык это `SKILL.md` плюс справочные файлы: когда применять, шаги с именами инструментов, проверка результата. Пишется под DeepSeek Flash (короткие императивы, явный порядок) и под Flux (промпты без брендов, размеры).
- Перед публикацией проверяется выбор навыка в свежем контексте, затем проводится пробный прогон с проверками фактических результатов инструментов. Прогон привязан к содержимому черновика и исходной версии; backend проверяет структуру и имена инструментов, владелец видит результат.
- Версии и откат, учёт применений именно той версии, которую загрузил ход. Оценка владельца привязана к конкретному применению; технические ошибки учитываются отдельно.
- Две отрицательные оценки разных применений текущей версии создают предложение улучшить навык. Новая версия проходит проверки и подтверждение владельца; автоматической публикации нет. Периодический навык можно дополнить расписанием.
- Только личный чат владельца и семейная группа; внешним группам навыки не выдаются.

### ⏰ Напоминания и автономные сценарии

- Напоминания: разовые, ежедневные, еженедельные; личные и семейные.
- Сценарии по расписанию с инструментами: «каждое утро собери погоду, календарь и почту», «в пятницу — сводка по новостям клуба».
- Напоминания учитывают настроенный часовой пояс и тихие часы; тихие часы действуют, если они включены.
- Для внешних групп — отчёты по расписанию с отдельным подтверждением владельца.

### 🎙 Голос, файлы и вложения

- Голосовые расшифровываются через Groq Whisper до основного хода.
- В личном и семейном чате разрешённые вложения сохраняются в доступную рабочую область; файлы можно отправить обратно в чат. Во внешней группе документы по умолчанию запрещены: отдельный grant разрешает только поддерживаемые UTF-8 текстовые форматы, без бинарных документов и архивов. Анализ фото регулируется отдельным правом.
- Изолированные области: файлы одной области не видны в другой.

### 📄 Документы

- В личном и семейном чате `pdf`, `docx`, `xlsx` помогают читать, править и собирать документы: договоры, таблицы, отчёты.
- Работа в sandbox-контейнере, результат приходит файлом.

### 🌐 Браузер и Google Workspace

- В личном и семейном чате `agent-browser` открывает сайты, заполняет формы и читает данные. В образ включены Chrome и Lightpanda; при ограничениях локального браузера предусмотрен Browserless с отдельным ключом. Успешное прохождение CAPTCHA не гарантируется.
- Google Workspace (Gmail, Calendar, Drive, Docs, Sheets, People) появляется при заданных OAuth-ключах; затем нужно авторизовать подключение. Внешним группам эти подключения не выдаются.

### 👨‍👩‍👧 Семья, приглашения, роли

- Bootstrap владельца по одноразовому коду при установке.
- Приглашение участника: владелец создаёт одноразовую ссылку → человек переходит → владелец подтверждает.
- Административные операции только в личном чате владельца, с повторной проверкой роли в базе перед выполнением.

### 💬 Группы

- **Семейная группа** (`family_private`): только подтверждённые участники семьи, семейная память, тот же набор инструментов, что и в личном чате, кроме личных данных.
- **Внешняя группа** (`external`): своя изолированная область, без личных и семейных данных, без Bash и произвольной сети.
- Режимы реакции: только по обращению, на все сообщения, либо только на сообщения владельца.
- Владелец выдаёт внешней группе allowlist из: память (`remember`, поиск, нити, конфликты), файлы (`read_file`, `write_file`, `glob`, `grep`, импорт и отправка вложений), `web_search`, `web_fetch`, `inspect_workspace_image`, `generate_image` (вместе с ним включается skill `imagegen`), история группы. Смена типа группы пересоздаёт зону доверия.

### 🎛 Подтверждения

- Подтверждения предусмотрены для конкретных операций: например, смены прав группы и публикации, отката или удаления авторского навыка. Tool-approval и вопросы ожидают ответа пять минут; затем ход продолжается без исполнения неподтверждённого действия. Для обновлений используется отдельное предложение владельцу.
- Создание, правка и мягкое удаление записей памяти не требуют HITL. Агент проверяет смысл изменения, backend независимо проверяет права и актуальность записи; удалённая запись скрывается из чтения и сохраняется на время окна восстановления.
- Ручная ротация контекста, когда тема сменилась и старый диалог мешает.

## Модель и провайдеры

Конфигурация задаёт отдельно основную модель (`agent.models.primary`) и обработку изображений
(`agent.models.vision`). Это две роли в приложении: они могут использовать один и тот же ID модели.

Проверенная конфигурация production на 14 сентября 2026 года:

| Параметр | Значение |
| --- | --- |
| Провайдер и транспорт | `deepseek`, `deepseek-responses`, `https://api.deepseek.com/responses` |
| Текст | `primary.id: deepseek-flash`, `reasoning.effort: high` |
| Фото | `vision.id: deepseek-flash`, `supportsImageInput: true`, `reasoningEffort: high` |
| Контекст основной модели / предел вывода | 1 000 000 / 128 000 токенов |

`supportsImageInput: true` разрешает приложению создавать модель для обработки изображений из
`vision.id`; этот флаг не переключает запросы на экспериментальную модель и не добавляет провайдеру
поддержку изображений. Разбор фото выполняется отдельным вызовом настроенной модели.

На production настройки хранятся в `/opt/osinara/agent-model-providers.json` и меняются через
`sudo osinara config`. Файл [`config/agent-model-providers.json`](config/agent-model-providers.json)
в репозитории отличается: в нём основная модель `deepseek-v4-flash` с effort `max`, а обработка фото
выключена (`supportsImageInput: false`). Установщик формирует конфигурацию по выбранной модели;
репозиторный файл не является снимком production.

Родной DeepSeek transport приводит запрос к поддерживаемому формату, передаёт глубину рассуждений,
читает `cached_tokens` и `reasoning_tokens`, преобразует HTTP-ошибки в стабильные коды.
Локальный патч Eve выбирает провайдерский backend `web_search` для DeepSeek.
Схема также поддерживает Chat Completions и Anthropic-совместимый транспорты DeepSeek, Groq,
OpenRouter, NeuralDeep и Codex-подписку.

## Как пользоваться

**1. Поставить на сервер.** Нужен GNU/Linux x86_64 (glibc), Docker Engine + Compose v2, свободные порты `80`, `443`, `8082`.
Установщик и образы берутся только из [релизов Мии](https://github.com/ilkruglov/osinara/releases/latest).
Образы собираются в CI после тестов; сервер ничего не собирает. Нужны также `jq`, `curl` и systemd.
Существующую установку обновляйте через подтверждённое предложение Мии: повторный `install` поверх БД запрещён.

Для установки релиза `1.0.1` (GitHub CLI нужен для скачивания и проверки артефактов):

```bash
gh release download v1.0.1 -R ilkruglov/osinara -p install.sh -p osinara-linux-x64.sha256
gh attestation verify install.sh -R ilkruglov/osinara
gh attestation verify osinara-linux-x64.sha256 -R ilkruglov/osinara
sudo sh ./install.sh \
  https://github.com/ilkruglov/osinara/releases/download/v1.0.1/osinara-linux-x64 \
  "$(cut -d ' ' -f 1 osinara-linux-x64.sha256)"
```

Установщик проверяет checksum бинарника и архива, создаёт изолированные области данных и добавляет
systemd-таймер обновлений. Команда `osinara` и пути `/opt/osinara` сохранены для совместимости существующих установок.

**2. Стать владельцем.** Перейдите по ссылке из установщика и напишите боту. Если ссылка не появилась —
`sudo osinara owner-bootstrap` выдаст новый код на 15 минут.

**3. Позвать своих.** В личном чате: «пригласи Анну» → отправьте ссылку → после её перехода подтвердите кандидата.

**4. Подключить группы.** Добавьте бота в группу и в личном чате владельца скажите, чем эта группа является:
семейной или внешней. Для внешней задайте режим реакции и allowlist прав; веб-поиск, vision и картинки выдаются там же.

**5. Дальше — обычным языком.** «Напомни в четверг про садик», «что нового по клубу, поищи», «что на этом фото»,
«нарисуй открытку к дню рождения», «собери из этих чеков таблицу», «каждое утро в 8 присылай сводку»,
«расскажи, что ты знаешь про Сашу», «что у нас было в августе».

**Обслуживание:**

```bash
sudo osinara status     # версия и доступность приложения
sudo osinara doctor     # диагностика установки
sudo osinara logs       # логи
sudo osinara restart    # перезапуск
sudo osinara config     # конфигурация модели и провайдера
```

Мия проверяет новые релизы `ilkruglov/osinara` каждые шесть часов и предлагает обновление владельцу в личном Telegram-чате.
После подтверждения сервер повторно проверяет владельца и релиз, останавливает обработчики, сохраняет обе БД
и рабочие файлы, применяет миграции и проверяет здоровье сервисов. Чужие репозитории и изменяемые релизы не принимаются.

## Локальная разработка

```bash
npm ci                      # postinstall применяет локальные Eve-патчи
cp .env.example .env        # заполнить обязательные секреты
docker compose up --build   # edge: http://localhost:8080
```

Полный список переменных — в [`.env.example`](.env.example): только секреты, доступы и привязки
к инфраструктуре. Поведение агента (таймауты, лимиты, расписания, настройки модели) живёт в
конфигурации в репозитории, а не в окружении. Отсутствующий обязательный секрет — ошибка на старте,
а не подставленное значение по умолчанию. Блоки Google Workspace и генерации картинок необязательны:
`CLOUDFLARE_ACCOUNT_ID` + `CLOUDFLARE_AI_TOKEN` и/или `NEURALDEEP_IMAGE_API_KEY` включают `generate_image`.

Проверки:

```bash
npm run typecheck && npm test && npm run build

# production-equivalent прогон
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests

# качество гибридного поиска с настоящими E5 и reranker
docker compose -f compose.test.yaml --profile memory-quality up --build --abort-on-container-exit --exit-code-from memory-evals memory-evals
```

Миграции запускаются только внутри backend/test-контейнера: `npm run migrate`.

## Безопасность

- Авторизация принадлежит приложению: identity, семья, роль и область доступа никогда не берутся из текста модели.
- Память, документы, сайты, результаты поиска и инструментов считаются недоверенными данными. Для файлов инструкции Мии требуют прекратить чтение и обработку, если обнаружены указания, адресованные ИИ-агенту.
- Отсутствие обязательного конфига — быстрая ошибка со стабильным кодом, а не догадка со значением по умолчанию.
- Внешние группы не получают личную и семейную память, учётные данные, Bash и произвольную сеть.
- Ключи провайдеров живут только в `.env` сервера и не попадают в логи и в текст модели.
