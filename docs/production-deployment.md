# Установка и обновления Мии

Источник релизов: `ilkruglov/osinara`; образы: `ghcr.io/ilkruglov/osinara-*`.
Сервер не клонирует репозиторий и не собирает приложение. Eve остаётся на версии `0.40.0`.

## Публикация

1. Изменить версию в `package.json` и корне `package-lock.json`, добавить `docs/releases/vVERSION.txt`.
2. Отправить изменения в `main`. При необходимости запустить `CI and release` через `workflow_dispatch` для `main`.
3. CI выполняет полный Docker-набор тестов и отдельные проверки поиска с E5 и reranker.
4. После тестов CI публикует шесть образов с digest и provenance, собирает standalone CLI и installation bundle.
5. Релиз сначала создаётся как draft. Все файлы скачиваются обратно и сравниваются побайтно, затем релиз публикуется как immutable.

В репозитории должна быть включена неизменяемость релизов. Пакеты GHCR должны быть публичными,
чтобы установка и обновление не требовали GitHub-токена на сервере. При первой публикации проверить
анонимное скачивание каждого образа. Опубликованный tag нельзя переносить; исправление требует новой версии.
Неполный draft можно продолжить только для того же commit SHA.

Артефакты: `osinara-deployment.json`, `compose.production.yaml`, `install.sh`,
`osinara-installation.tar.gz`, `osinara-linux-x64` и `osinara-linux-x64.sha256`.
Manifest версии 1 связывает версию, commit, SHA-256 Compose и digest шести образов.
Обычная установка с прямым провайдером не запускает subscription gateway; существующий gateway
сохраняется при обновлении. Альтернативные провайдеры остаются доступными в приложении.

## Первая установка

Требуются GNU/Linux x86_64 на glibc, root, Docker Engine с Compose v2, systemd, curl и jq;
порты 80, 443 и 8082 должны быть свободны. Команды загрузки и проверки находятся в README.

Bootstrap проверяет SHA-256 бинарника до запуска. Бинарник содержит версию и hash ровно одного
installation bundle. Архив проверяется по размеру, типам, путям и правам файлов до записи от root.
Установщик запрашивает адрес, Telegram и выбранного провайдера, проверяет доступы и создаёт отдельный
Workflow PostgreSQL connection. Секреты хранятся в `/opt/osinara/.env` с правами `0600`.

После успешных миграций, healthcheck и bootstrap владельца устанавливаются systemd-служба и таймер.
Повторная установка поверх существующих каталогов, контейнеров или томов запрещена.
До начала миграций неудачная попытка может удалить только созданные ею файлы; после начала миграций
данные сохраняются для ручной проверки.

## Обновления установленной Мии

Агент проверяет последний релиз нашего репозитория каждые шесть часов. Отсутствие первого релиза
означает отсутствие обновлений. Ссылки на upstream, чужие GHCR namespace, mutable, draft и prerelease
не принимаются. Предложение связано с актуальным владельцем и подтверждается в его личном чате.

`osinara-deploy.timer` раз в минуту вызывает root-owned `/opt/osinara/bin/production-deploy.sh`.
Контроллер берёт lock и одно подтверждённое предложение, повторно сверяет владельца, immutable release,
tag/commit, manifest и Compose hash. Граф Compose проверяется на точный набор сервисов, образов,
mounts и сетевых прав. Все образы скачиваются до остановки приложения.

После проверки свободного места останавливаются сервисы, кроме PostgreSQL, сохраняются обе БД,
рабочие файлы и конфигурация. Дампы проверяются через `pg_restore --list`, архивы через `tar -tzf`,
затем записываются SHA-256. Новая версия запускается с migration gate и healthcheck.
Только после успеха обновляются `compose.installation.json`, `release.env` и manifest установки.
Сохраняются два последних завершённых deployment backup; ручные резервные копии не удаляются.

До миграций возможен перезапуск прежней версии. Ошибка после начала миграций получает статус
`ambiguous`: автоматическое восстановление БД и повтор действий запрещены. Истёкший lease также
не повторяется автоматически. Root-пути и существующие Docker-тома не переименовываются.

## Файлы и обслуживание

| Путь | Назначение |
| --- | --- |
| `/opt/osinara/.env` | Секреты, root:root `0600` |
| `/opt/osinara/agent-model-providers.json` | Выбранная пользователем модель |
| `/opt/osinara/compose.installation.json` | Текущий граф установки |
| `/opt/osinara/release.env` | Digest образов текущего релиза |
| `/opt/osinara/osinara-deployment.json` | Manifest текущего релиза |
| `/opt/osinara/bin/production-deploy.sh` | Updater, root:root `0750` |
| `/opt/osinara/bin/production-deploy/` | Четыре root-owned модуля `0640` |
| `/opt/osinara/backups/` | Дампы, архивы и контрольные суммы |
| `/opt/osinara/releases/` | Проверенные файлы установленных релизов |

`osinara status`, `doctor`, `logs`, `restart`, `config` и `owner-bootstrap` работают с тем же форматом
установки. Healthcheck доступен локально по `http://127.0.0.1:8082/eve/v1/health`.
Первый переход существующего форка на собственные релизы выполняет оператор из успешного CI с
резервной копией, сохранением `.env`, модели, БД и томов, установкой собственного controller и manifest.
Исторические provider/Workflow bridges upstream в новой цепочке отсутствуют.
