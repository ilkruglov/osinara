# v0.21.4: независимые чаты, подтверждения, кэш и быстрая синхронизация скиллов

## Подтверждения и очереди

- Нажатие кнопки в личке больше не ждёт ответа другой группы. Убран общий `activeDrain`, а порядок
  сообщений внутри одного chat/topic продолжает защищать PostgreSQL. Регрессия воспроизводит четыре
  подтверждения, пока первый групповой ход ещё не завершён.
- Нагрузка ограничена двумя обычными ходами и двумя отдельными callback-проходами одновременно:
  занятые группами места не блокируют кнопки. Повторные сигналы одной очереди не создают второй её ход.
- Продолжение подтверждения и отмена по таймауту не создают отдельный ответ после финального.
  Служебный контекст располагается перед восстановленным транскриптом подтверждения, поэтому AI SDK
  видит разрешённые действия и исполняет их один раз. Проверены четыре последовательных решения,
  смешанное разрешение/отмена, текстовое подтверждение и настоящий новый запрос.
- Callback не считается новым Telegram-сообщением с фактами. Настройки чата читаются с актуальной
  проверкой доступа, а запись памяти и предпочтений не предлагается без нового проверенного сообщения.
- Подтверждения изменения инструментов/скиллов показывают название зарегистрированной группы и её ID.
  Название берётся из данных семьи владельца; неизвестная группа вызывает ошибку до создания окна.

## Модель и Workflow

- Текущая подборка памяти переносится из system в конец запроса модели, не меняя сохранённую историю.
  Стабильная часть запроса не меняется из-за появления/исчезновения подборки; сжатие истории не требует
  сохранности исходного вопроса, пары вызова инструмента и результата не разрываются.
- Потоковый OpenAI-compatible запрос явно запрашивает usage. Метрики различают отсутствующие счётчики
  и присланный ноль, измеряют задержки и стабильность запроса без записи текста, ключей или рассуждений.
  Добавлены длительности retrieval, инструментов и синхронизации скиллов.
- Внутренний HTTP Workflow больше не обрывает долгую обработку по стандартному пятиминутному ожиданию
  заголовков. Установлено отдельное окно 35 минут. Повтор живой доставки присоединяется к исполнению,
  новые доставки не теряются; сохранены нативная сериализация и существующие durable-барьеры приложения.
  Барьер действует внутри текущего одного runtime-процесса, не является гарантией между репликами.

## Скиллы

- Вместо последовательных запросов для каждого файла backend передаёт один полный пакет. Проверяются
  реальные байты объявленных файлов; неизменённые не перезаписываются, изменённые восстанавливаются.
- В окружениях с Bash проверка выполняется доверенным Node самого runner, а не изменяемым моделью
  interpreter. Restricted tmpfs использует абсолютный Node закреплённого образа и приватный stdin.
- Сохранены текущие mounts, права и файловые пути. Live allowlist и точный instance ID перепроверяются;
  отмена HTTP останавливает работу, а замена контейнера не позволяет исполнить старую заявку в новом.
- При остановке runner сначала закрывает приём запросов и дожидается принятых операций и фоновой
  очистки. Только затем удаляется окончательный набор контейнеров; запись файлов не переживает замену
  своего экземпляра, а отмена после Docker HTTP upgrade останавливает зависший процесс.
- Проверены кириллические пути при разбиении входных байтов, подмена каталога symlink, восстановление
  многогигабайтного повреждённого файла без его загрузки целиком и сохранность пользовательских данных.
- Временные файлы после принудительной отмены остаются под зарезервированными именами в корне
  каталога skills и очищаются следующим проходом под блокировкой тома; пользовательские файлы не удаляются.

В двух изолированных проверках на настоящем Docker повторная синхронизация 135 файлов заняла 196-603 мс,
не перезаписав ни одного файла. Это измерение синхронизации, не обещание такой же длительности ответа модели.

## Совместимость

Eve остаётся 0.40.0, Postgres World 5.0.0-beta.35; миграций и смены провайдера нет. Исправления сетей и
потоков из v0.21.3 сохранены. История, память, browser auth и установленные инструменты не удаляются.
Файлы скиллов не становятся неизменяемыми: Bash сохраняет доступ к собственному окружению. Проверка
контролирует manifest при синхронизации, но не выдаёт файлам дополнительных полномочий.
