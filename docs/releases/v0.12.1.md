# Osinara v0.12.1

Исправлено создание независимых нитей памяти после перехода на решения основного чат-агента в
`v0.12.0`. Короткие русские E5 embeddings имели высокий общий baseline, поэтому широкий retrieval
threshold ошибочно блокировал новую тему «Похудение» как похожую на существующую нить «Инвестиции».

## Исправление candidate guard

- Поиск и автоматическая активация нитей сохраняют широкий semantic threshold `0.78`, необходимый для
  recall при пользовательских запросах.
- Создание новой нити получает отдельный creation-only threshold `0.92`; duplicate prevention больше
  не переиспользует retrieval calibration.
- Production-диагностика показала `0.837-0.891` между пятью фактическими вариантами темы здоровья и
  нитью «Инвестиции». Все они теперь проходят candidate guard.
- Проверенные близкие пары остаются заблокированы: «Марафон 2027» / «План марафона» дали `0.925`,
  «Инвестиции» / «Инвестиционный план» `0.953`, «Ремонт кухни» / «Кухонный ремонт» `0.987`.
- Exact normalized title по-прежнему детерминированно прикрепляет claim к active thread. Purpose
  trigram gate `0.9` и transactional rollback кандидата не изменены.

## Точный контракт `remember`

- Для root-нити текущего автора модель больше не передаёт `identity`, `subjectRef` или `subjectLabel`:
  backend выводит verified subject только из текущего Telegram source.
- `personal + project` и свободный `subjectLabel` при создании нити отклоняются Zod schema до E5 и
  PostgreSQL transaction со стабильным кодом `AGENT_MEMORY_THREAD_INPUT_INVALID`.
- Project identity остаётся доступна для общей памяти нескольких участников; verified `subjectRef`
  остаётся точным способом выбрать другого известного субъекта.
- Model-facing schema descriptions объясняют эти ограничения до первого tool call.

## Ограничение повторов и честный результат

- После `AGENT_MEMORY_THREAD_CANDIDATE_EXISTS` агент читает сомнительного кандидата и либо выполняет
  explicit attach, либо делает ровно одну попытку с уточнёнными title и purpose.
- Повторный результат с тем же кандидатом завершает попытки; backend error и prompt одновременно
  запрещают дальнейший цикл переименований.
- Агент больше не обещает, что нить «создастся автоматически позже». После удаления background thread
  discovery в `v0.12.0` создание или прикрепление подтверждается только успешным результатом
  `remember`.
- Неудачные thread create остаются atomic: rejected claim и временный project не сохраняются. Обычная
  запись без thread создаётся только отдельным осознанным вызовом основного агента.

## Проверка

- Production-equivalent Docker Compose gate: `231` test files passed, `1` skipped; `1224` tests
  passed, `1` skipped.
- Локальный Vitest: `171` test files passed, `61` skipped; `1011` tests passed, `214` skipped.
- Database integration проверяет рабочее окно cosine: distinct topic `0.90` создаёт вторую нить, а
  semantic duplicate `0.925` отклоняется с rollback и bounded-retry сообщением.
- Tool schema tests проверяют valid current-author personal create и ранний отказ невозможных identity.
- Mode isolation tests подтверждают отсутствие утечки personal/family/group возможностей между
  trust zones.
- `npm ci`, `npm run typecheck`, `npm run build` и `npm run build:runtime` прошли; Eve compiled
  manifest содержит `0` errors.

## Production deployment

- Database migration, Compose graph, controller allowlist и root-owned deployment modules не менялись.
- Release публикуется только из canonical `main` через GitHub Actions с immutable GHCR digests,
  attestations и exact release assets.
- Установка требует отдельного owner approval в привязанном личном Telegram-чате.
