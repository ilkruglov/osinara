# Оставшаяся работа

## Статус

Здесь перечислено только то, что ещё не реализовано или требует отдельного продуктового решения.
После завершения задачи её нужно удалить из этого документа, а не дополнять историей реализации.

## Качество долговременной памяти

### Смысловые дубли

- Собрать измеримый набор реальных дублей и похожих, но разных фактов.
- Определить безопасные правила: когда усиливать существующий факт, когда связывать два факта, а
  когда оставлять их раздельными.
- Добавить консолидацию похожих кандидатов внутри одного memory review batch.
- Не включать автоматическое объединение до проверки recall, false merge и сохранности evidence.

### Надёжность источников

- Передавать background memory review явный trusted-список допустимых `sourceSequence`.
- Ограничить model-facing контракт текущим batch, сохранив обязательную серверную проверку source.
- Для точного повтора уже завершённой операции находить terminal replay до требования живого source
  binding. Новый memory write без проверенного источника по-прежнему должен отклоняться.

### Политика полезности

- Определить по режимам `personal`, `family` и `external`, какие факты действительно стоит хранить.
- Отдельно решить правила для краткоживущих планов, пересказов, оценочных суждений, конфликтующих
  утверждений и чувствительных данных.
- Зафиксировать эти правила в eval-наборе до изменения prompt или write policy.

### Наблюдаемость и очистка

- Измерять число просмотренных сообщений, кандидатов, новых claims, reinforcements, отказов и
  смысловых дублей по scope без записи содержимого памяти в логи.
- Различать в метриках неверный `sourceSequence` от повтора завершённой операции без живого source
  binding, чтобы ошибки модели не смешивались с особенностями Eve replay.
- После утверждения правил выполнить отдельную dry-run проверку существующих дублей.
- Любое массовое объединение или удаление проводить отдельной обратимой операцией с сохранением
  evidence и audit trail.

## Workflow replay

- Устранить неограниченный рост replay из-за cumulative Eve stream, чтобы можно было безопасно снять
  ротацию session после 50 завершённых turns.
- Следить за upstream-решением Eve для cumulative `messageSoFar` и `reasoningSoFar`; не исправлять
  протокол скрытым локальным patch.
- Перед снятием лимита пройти deterministic stress gate минимум на 300 последовательных turns:
  bounded replay latency, отсутствие timeout, корректное resume после restart и отсутствие повторных
  tool side effects.
- В том же gate измерить строки, bytes и chunks Workflow tables и доказать физическое удаление
  terminal runs после retention boundary.

## Идеи OpenViking, требующие решения

Эти пункты не являются утверждённым планом. Их следует реализовывать только при подтверждённой
пользовательской задаче и после отдельного проектирования.

### Единый контекст документов

- Решить, нужен ли отдельный resource plane для документов, заметок и других больших материалов.
- Если нужен, спроектировать versioned resources, derived representations уровней L0/L1/L2 и
  строгую привязку каждой версии к authorization scope.
- Определить ingestion, обновление, удаление и повторную индексацию без смешивания семейных, личных и
  внешних данных.

### Планирование retrieval

- Решить, нужен ли единый budget planner для memory, threads, timeline, resources и skills.
- Если нужен, сделать typed query plan, иерархический retrieval и полный trace: что нашли, что
  отбросили, почему это попало в model context и сколько бюджета заняло.
- Проверить улучшение качества и latency на eval-наборе до замены существующего scoped retrieval.

### Skills и накопленный опыт

- Проверить практическую пользу semantic skill discovery по сравнению с текущим явным allowlist.
- Не вводить trajectories, автоматическое извлечение опыта или self-evolution без отдельной модели
  угроз, правил подтверждения и измеримого пользовательского эффекта.
- Не добавлять внешний context API или MCP surface без конкретного потребителя и нового аудита
  authorization boundary.

## Порядок работы

1. Политика полезности памяти и eval-набор.
2. Смысловые дубли, source reliability и метрики.
3. Подтверждённое решение проблемы Workflow replay.
4. Отдельное продуктовое решение по resource plane и retrieval planner.
5. Skills, trajectories и внешний API только после доказанной необходимости.
